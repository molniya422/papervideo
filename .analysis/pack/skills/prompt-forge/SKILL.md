# Prompt Forge · 生成前的提示词锻造

生成视频最贵的错误是"方向错了还渲了 9000 帧"。本技能把需求先锻造成合同：
**内容边界、视觉规则、禁止清单、镜头节奏、验收阈值**。产出 `brief.md` 后才允许写代码。

## 何时必须跑

- 任何"做一条讲解视频 / 动画 / MV / 宣传片"的请求；
- 用户只给了一个链接、一段文字或一句"做个视频"；
- 上一版被打回、需要重做时（先改 brief，不要直接改代码）。

## 输入

最少需要：主题/论文、目标受众、期望时长、成品形态（横版/竖版）、语言。
缺什么就用默认值并在 brief 里写明假设，**不要停下来连问五个问题**；只有"没有主题"才必须问。

## 流程（五步）

### 1. 三套差异化方案

先给三个真正不同的方向，而不是同一套的三档预算。差异必须体现在：

| 维度 | 三案之间必须不同 |
|---|---|
| 视觉隐喻 | 例如：机械装置 / 空间漫游 / 数据仪表盘 |
| 镜头语言 | 例如：宏观推拉 / 剖面跟随 / 平面信息图 |
| 技术路线 | 例如：three.js 3D / 纯 SVG 2D / 实拍+合成 |
| 时长节奏 | 例如：45 秒预告 / 3 分钟讲解 / 6 分钟深讲 |

每个方案给：一句话概念、参考风格（找得到的具体作品或网站）、关键镜头 3 个、预估渲染时间、风险。
**让用户选一个**；用户不在场时选"最能承载解释"的那个，并在 brief 里记录理由。

### 2. 写 brief.md（XML 分区，不用 Markdown 堆砌）

结构固定，字段见 `templates/brief.xml`：

```xml
<role>导演 + 动效工程师，不是文案助手</role>
<subject>这篇论文要解释的唯一问题</subject>
<audience>前置知识、看完要能回答什么</audience>
<duration>总时长与镜头数上限</duration>
<style>视觉规则：配色、字体、构图、运动曲线</style>
<forbidden>具体禁止项（见第 3 步）</forbidden>
<storyboard>逐镜头表：秒数 / 画面 / 旁白要点 / 3D 主体</storyboard>
<tech>渲染栈、分辨率、帧率、音频方案</tech>
<pitfalls>已知坑：字体未加载、热力图色彩空间、缩放层级…</pitfalls>
<acceptance>可打分的验收标准（见第 4 步）</acceptance>
```

### 3. 写"具体"的禁止清单

泛泛的"不要 low"没有用。禁止项必须能一眼判断违没违反：

- 不要深色背景 + 居中大字当默认页；
- 不要无动机的粒子爆炸、镜头抖动、发光描边；
- 不要匀速线性运动（所有位移必须有缓动）；
- 不要用 emoji 当图标；
- 不要在 3D 画面上叠长段文字（文字只能进文字区/字幕带）；
- 不要"首先/其次/总之/值得注意的是"这类 AI 套话；
- 不要给柱状图用零基线却宣称"差距巨大"（截断轴要标注）。

### 4. 写"大胆变换"条款（新增，默认必填）

形式单调是视频最容易被判"平庸"的原因。brief 里必须回答：

- **图形族清单**：本片至少 3 套可互相变形的图形（例：半调点阵 / 齿轮 / 仪表 / 等距爆炸图 / 示波器 / 铆接板）；
- **每章形变**：每章至少 2 次形态变化，写清"从什么变成什么、在第几秒"；
- **章节转场**：每 45 秒至少一次形式转场（机械光圈、闸门合拢、扫描擦除、拆解重组），禁止纯硬切过场；
- **主视觉突出**：每章至少一个占画面 ≥35% 的图形主体，且对比度最高；
- **禁止**：连续 20 秒只有同一形态的位移/淡入；只换颜色不换形态；图形全部退居背景。

### 5. 定义可打分的验收标准

每个维度 0–10 分，**低于 8 分不交付**。至少覆盖：

| 维度 | 8 分意味着 |
|---|---|
| 前 2 秒 | 有信息量，不是 logo 动画 |
| 可读性 | 手机尺寸下字幕与标签可读，无文字压图 |
| 解释力 | 每个镜头只讲一件事，看完能复述因果链 |
| 运动质量 | 无匀速、无空拍，每 2–4 秒有新变化 |
| 音画同步 | 字幕与旁白逐句对齐（由音频时长驱动） |
| 技术卫生 | 抽帧无糊字/穿模/接缝，响度达标 |
| 变换密度 | 每章 ≥2 次形变、每 45 秒一次形式转场、≥3 套图形族 |

### 5. 交给生成技能

brief.md 定稿后，再调用 `remotion-video` / `knowledge-explainer-skill` / `hyperframes`。
生成过程中的任何"想改方向"都必须先改 brief，再改代码——否则最后没人知道在验收什么。

## 与其它技能的配合

- 文案写完先过 `humanize-writing`（去 AI 味），再进 brief；
- 视觉方向参考 `design-taste-frontend`（反模板化、从主题本身长出概念）；
- 路线与交付检查参考 `video-production-guide`（纯代码/图像+代码/视频+代码/产品界面四条路线）；
- 验收后必须跑 `video-retrospective` 做总结归纳。
