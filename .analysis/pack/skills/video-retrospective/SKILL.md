# Video Retrospective · 验收后的总结与归纳

片子渲完、抽帧通过，工作只完成了 80%。剩下 20% 是把经验变成下一次的默认值，
否则同样的坑下一支片子还会踩。

## 触发时机

- 用户验收通过（或明确说"可以了"）之后；
- 被打回重做之前，也先写一份"失败复盘"，再动手改；
- 一个项目有多支视频时，每支都要写，最后汇总到项目级 `lessons.md`。

## 输出（两个文件）

### 1. `6-review/retrospective.md`（单支视频）

固定结构，不要写成流水账：

```markdown
# <片名> 复盘

## 一句话结论
这支片子最后站住了/没站住，因为 ______。

## 打分（0–10，低于 8 的必须写原因）
| 维度 | 分数 | 证据 |
|---|---|---|
| 前 2 秒 |  |  |
| 可读性 |  |  |
| 解释力 |  |  |
| 运动质量 |  |  |
| 音画同步 |  |  |
| 技术卫生 |  |  |
| 变换密度 |  |  |

## 有效的东西（可复用）
- 具体到做法层面，例如"逐句音频驱动字幕，字幕与语音同源，零不同步"

## 无效的东西（别再犯）
- 现象 → 根因 → 修复 → 固化成哪条规则

## 数据
实际时长 / 镜头数 / 渲染耗时 / 返工轮次 / 文件大小 / 响度

## 下一支片子的默认值
把这次学到的，写成 3–7 条下次直接照做的默认设置。
```

### 2. `lessons.md`（项目级累积）

只写**可迁移的规则**，不写具体画面。每条格式：

```
- [类别] 规则 —— 由哪次经历得来
```

示例：
```
- [字幕] 字幕必须由逐句音频时长驱动，禁止按权重切分镜头时长 —— v1 字幕错位
- [3D] scale 必须套在定位组内层 —— v2 元素被拉回原点
- [色彩] DataTexture 必须设 SRGBColorSpace —— v2 热力图发白
```

## 变换密度怎么打

数出来：全片形变次数 / 章节数、形式转场次数 / 分钟、图形族数量。
每章 ≥2 次形变、每 45 秒 ≥1 次转场、≥3 套图形族，缺一项扣 2 分；
连续 20 秒只有位移或淡入的段落，每段扣 1 分。

## 打分要求

- 必须给出**证据**（抽帧编号、时间点、用户原话），不能只写"感觉不错"；
- 低于 8 分的维度，必须写"为什么这次没做到"和"下次怎么保证"；
- 用户没验收就自己宣布完成的，视为失败项，直接记 5 分以下。

## 归纳的层次

1. **单支片子**：哪些镜头有效、哪些无效；
2. **工作流**：哪个阶段该前置、哪个验收门形同虚设；
3. **技能**：把稳定结论写回对应技能（`prompt-forge` 的禁止清单、`remotion-video` 的铁律、
   `paper-explain` 的质量底线），确保下一次默认生效。

## 完成判据

- `retrospective.md` 写完且每个分数有证据；
- 至少向 1 个技能写回了 1 条硬规则（或说明为什么这次没有新规则）；
- `pipeline-state.json` 标记 `retrospective: done`。
